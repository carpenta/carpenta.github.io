## 일하는 방식

- **라운드마다 버전 +1.** 한 라운드(한 가지 개선 묶음)가 끝나면 `VERSION`을 올리고 `IMPROVEMENTS.md` 맨 위에 항목을 씁니다(바뀐 것, 이 라운드가 정한 것, 확인, 남긴 것). 여러 브랜치를 나란히 진행하면 번호는 합칠 때 다시 붙입니다.
- **배포는 사용자가 "배포"라고 할 때만.** `master` 푸시가 곧 실서비스 배포입니다. 브랜치 → PR → GitHub Actions(Linux) 통과 → 병합 → 배포 확인 순서입니다. 배포 확인은 캐시를 피한 주소(`?v=<커밋>`)로 받은 번들에 새 버전이 있는지로 합니다.
- **화면을 바꾸는 라운드는 디자인 검토를 함께.** 정렬은 눈으로 보지 않고 DOM에서 재고(360·375·390px, 큰 글씨, 넓은 글자), 1px 안을 e2e로 고정합니다. 바꾸기 전후 스크린샷을 같은 장면으로 찍어 비교합니다.
- **테스트를 먼저.** 동작을 바꾸면 실패하는 테스트를 먼저 쓰고 실패를 확인합니다. `.skip`/`.only`나 기대값을 느슨하게 하는 것은 하지 않습니다.
- **무거운 검사는 하나씩.** 단위 → 빌드 → Chromium e2e → WebKit e2e 순서로, e2e는 `--workers=1 -x`(첫 실패에서 멈춤). 실패하면 그 테스트만 고쳐 다시 돌린 뒤 전체를 다시 돌립니다. 다른 세션과 동시에 돌리면 WebKit이 시간 초과로 흔들리니, 그때는 그 테스트만 따로 다시 돌려 확인합니다.

```sh
cd tools/fairway-note
npm ci
npm test -- --bail 1
npx tsc --noEmit && npm run build
CI=1 npx playwright test --workers=1 -x                                     # Chromium, 포트 4175
CI=1 npx playwright test -c playwright.webkit.config.ts --workers=1 -x      # WebKit(iPhone), 포트 4185
```

`CI=1`은 이미 떠 있는 다른 미리보기 서버를 재사용하지 않게 합니다. 같은 컴퓨터에서 여러 세션이 돌면 세션마다 포트를 다르게 하는 로컬 설정 파일(커밋하지 않음)을 씁니다.

## 지켜 온 사용자 결정

바꾸기 전에 사용자에게 묻습니다.

- 팔레트 A: 짙은 러프 바탕에 노란빛 연두 강조. 화면마다 바탕 6색·반지름 3·그림자 3·글자 크기 5 이하, 반투명 바탕 없음. 예외 하나: 기록 머리줄의 칩(Par·거리, 진행, 홀 안내)은 홀 그림이 비치는 반투명(흰색 72%, v38).
- 클럽 캡슐: 위 반을 누르면 +1, 아래 반을 누르면 −1, 두 톤. +·−는 원 없이 캡슐 위에 비치는 잉크(60%, 구분선과 0일 때의 −는 35%). 가운데 구분선은 점선(v38). 클럽 이름을 누르면 샷 세부 패널.
- 이름: 기본은 티샷·그린까지·퍼터, 상세는 티샷·세컨·어프로치·퍼터. 저장 키는 예전 그대로 `approach`.
- 화면: 아래 막대 하나(스코어카드·기록·지난 라운드·메뉴). 모든 화면 왼쪽 위의 "홈"은 기록 화면으로 가고(앱 밖으로 나가지 않음), 사이트 링크는 메뉴 › 앱 정보에. 스코어카드는 스코어카드 | 분석 전환.
- 홀 그림: 야디지북 같은 평평한 평면도, 티는 왼쪽·그린은 오른쪽으로 보이는 띠 안에 맞춤(띠가 50px보다 낮으면 머리줄의 작은 그림). 100·150은 그린 중앙까지.
- OpenStreetMap: 에버리스 홀은 OSM 모양(ODbL). 그림 위 출처는 회색 글자만(배지·링크 없음), 물을 피해 좌우를 고릅니다. 저작권 링크는 홀 안내와 앱 정보에.
- 말로 입력은 기본 꺼짐(키보드 받아쓰기 + 한국어 명령 해석, 마이크·네트워크 접근 없음).
- 오프라인 전용: 런타임 외부 요청 없음, CSP 그대로, 저장 형식 호환.

## 넣으면 안 되는 것

- 골프존·골프장의 코스 약도(약관·저작권). 다른 앱의 이미지·아이콘·문구.
- OpenStreetMap 자체를 고치는 일(공개 지도 편집)은 사용자가 따로 요청할 때만.
- 런타임에 데이터를 받아 오는 것. OSM 데이터는 `npm run osm:holes`로 손으로 받아 `src/data/osm/`에 넣습니다(빌드·CI에서 받지 않음).

## 남은 일 (후보)

- 레이크 4·5번 홀: OSM에 4번 그린과 홀 선이 없어 도식으로 그립니다(OSM 편집이 필요).
- 다른 코스의 OSM 모양(OSM에 홀 선이 있는 곳부터).
- 각 라운드의 "남긴 것"은 `IMPROVEMENTS.md`의 각 항목 끝에 있습니다.
- 워치 앱은 별도 계획 단계이고 이 저장소에서 진행하지 않습니다.

## 자주 걸리는 것

- **Linux CI의 글꼴.** 숫자 폭·기준선 검사는 Linux의 힌팅에서 1px씩 달라질 수 있어 `text-rendering: geometricPrecision`을 씁니다. 로컬(macOS)에서 통과해도 PR의 Actions 결과를 봅니다.
- **WebKit 스크린샷과 CSP.** 픽셀을 읽으려고 `page.screenshot`을 쓰는 e2e는 WebKit이 자기 스타일을 넣어 CSP 오류가 나므로, 그 describe에만 `bypassCSP: true`를 둡니다(이유를 주석으로).
- **칠하는 색 세기.** 그림의 색 수 검사는 화면에 칠해진 색만 셉니다. 선으로만 그리는 path에는 `fill="none"`을 줍니다(기본 검정이 색으로 세어짐).
- **번들 크기.** 주 번들이 500KB 경고 바로 아래입니다. 큰 것을 더하면 나눠 불러오기를 생각합니다.
- **zsh.** `"$sha:path"`처럼 변수 뒤에 `:`가 오면 zsh가 수식어로 읽습니다. `"${sha}:path"`로 씁니다. 따옴표 없는 변수는 낱말로 나뉘지 않습니다.
