# Fairway Note — 골프 스코어 노트

> 이 도구의 작업을 이어받는다면 먼저 [docs/HANDOFF.md](docs/HANDOFF.md)를 읽으세요: 지금 상태, 일하는 방식, 지켜 온 결정, 남은 일.

라운드 중 휴대폰으로 홀마다 드라이버·그린까지·퍼터 스윙을 한 번씩 눌러 세고(상세에서는 그린까지를 세컨·어프로치로 나눠 셈), OB·해저드 벌타와 멀리건을 함께 표시하는 정적 웹 앱입니다. 기록 화면에는 지금 치는 홀만 보이고, 합계·스코어카드·분석은 스코어카드 화면에 모았습니다. 끝낸 라운드는 지난 라운드로 보관해 추세를 보고, 백업 파일로 다른 기기에 옮길 수 있습니다. TypeScript + Vite로 만들었고 백엔드, 계정, 분석 도구가 없습니다. 런타임 의존성은 앱에 함께 묶어 배포하는 글꼴(Pretendard) 하나입니다.

## 실행

Node.js 22.12 이상이 필요합니다.

```sh
npm ci
npm run dev
```

배포 빌드 확인:

```sh
npm run build
npm run preview -- --port 4175 --strictPort
```

주소: http://127.0.0.1:4175

CSP 때문에 `npm run dev`에서는 자동 새로고침(HMR)과 Vite가 넣는 스타일이 막힙니다. 화면은 빌드 후 미리보기로 확인합니다.

## 기능과 제한

- 코스 선택(첫 화면 "어디서 치세요?"): 러프색 바탕에 검색 칸, 지역 칩, 흰 카드 목록이 있고, 고른 코스는 아래 시트에서 전반·후반을 고르고 시작합니다. 열 때 코스 선택 화면이 먼저 나옵니다. 저장된 라운드가 없을 때, 예전 버전이 아무것도 기록하지 않은 채 저장해 둔 라운드만 있을 때, 다른 날 기록하던 라운드가 남아 있을 때입니다. "새 라운드 시작"을 누를 때도 열립니다. 코스 선택은 화면 전체를 덮어 왼쪽 위의 홈까지 가리므로, 첫 실행에는 제목 오른쪽(다른 때 취소가 있는 자리)에 사이트로 돌아가는 "홈" 칩(위 줄의 홈과 같은 집 아이콘, 화면 읽기 이름은 "홈, carpenta.github.io로 돌아가기")이 있습니다. 홈과 취소는 같은 44px 유리 칩이고 가운데가 제목의 가운데에 맞아, 어느 쪽이 보여도 제목이 같은 자리에 있습니다(v29).
  - 지난번에 고른 코스와 전·후반 9홀이 미리 골라져 있어 "이 코스로 시작" 한 번으로 시작합니다. 처음에는 에버리스 골프리조트 새별(전반)·레이크(후반)입니다. 고른 코스는 `fairway-note:prefs:v1`에 기억합니다.
  - 목록은 고른 코스의 줄을 맨 위에 두고 열리고, 밀면 줄 단위로 멈춥니다(반 줄에 걸치지 않음). 아래 시트의 제목은 코스 이름만이고(전·후반은 바로 아래 줄), 긴 이름도 두 줄까지 고르게 나눠 끝까지 보입니다. 코스 바꾸기처럼 홀 수가 정해진 때는 18홀/9홀 자리에 "9홀"이나 "18홀"이 나옵니다.
  - "이 코스로 시작"은 늘 화면 안에 있습니다. 글자가 넓은 기기에서 시트가 길어지면 목록이 남는 높이만(최소 한 줄 반) 쓰고, 그래도 모자라면 코스 이름과 전·후반 줄이 시트 안에서 스크롤됩니다.
  - 골프장 이름, 초성(예: `ㅇㅂㄹㅅ`), 지역으로 찾고, 지역 칩(제주·수도권·강원·충청·전라·경상)으로 좁힙니다.
  - 9홀 코스가 셋 이상인 골프장은 전반·후반을 고르고, 둘인 골프장은 바로 정해지며 "전·후반 바꾸기"로 순서만 바꿉니다. 9홀짜리는 두 번 돕니다.
  - 코스 이름 줄의 18홀/9홀에서 9홀을 고르면 후반이 없어지고 그 줄 이름이 "코스"가 됩니다. 라운드·홀 목록·진행 막대·스코어카드·요약이 9홀로 움직이고, 지난 라운드와 보고서에는 "에버리스 골프리조트 새별 9홀"처럼 남습니다. 고른 홀 수도 다음 라운드를 위해 기억합니다. 코스 바꾸기에서는 라운드의 홀 수를 바꾸지 않습니다.
  - 처음 화면에서 저장된 라운드나 지난 라운드를 읽을 수 없을 때, 또는 홈 화면 앱인데 기록이 하나도 없을 때(브라우저가 정리했을 수 있음) 코스 목록 위에 안내 카드가 나옵니다. "백업 파일에서 복원"은 메뉴의 백업 가져오기와 같고, 결과를 카드에 보여 주며, 진행 중이던 라운드를 되살리면 그 라운드로 바로 갑니다.
  - 목록에 없는 골프장은 "직접 입력"으로 이름을 넣고 모든 홀 Par 4로 시작합니다.
  - "새 라운드 시작"에서 코스 선택을 취소하면 지금 라운드가 그대로 남습니다.
- 화면은 세 개(스코어카드, 기록, 지난 라운드)이고, 화면 아래 짙은 막대 하나가 앱의 길 전부입니다(v32): 스코어카드 · 기록 · 지난 라운드 · 메뉴, 같은 폭 네 칸. 셋은 화면 탭, "메뉴"가 메뉴 시트를 엽니다. 전에 화면마다 왼쪽 위에 있던 ☰은 엄지가 닿는 이 막대로 옮겼습니다. "홈"(집 아이콘과 이름, v37부터 기록 화면으로 가고 사이트 링크는 앱 정보에)은 막대를 떠나 모든 화면의 왼쪽 위, 위 줄과 같은 높이에 조용한 글자로 있습니다(배경 없음, 48px). 막대에서는 화면 탭 사이에 있어, 스코어카드를 누르려다 앱을 떠날 수 있었습니다. 화면은 한 번, 메뉴의 항목은 두 번 눌러 닿습니다. 대화상자(클럽 패널, 홀 목록, 0–5+ 고르기, 홀 안내, 시트)가 열려 있는 동안 막대는 40%로 물러납니다(짙은 막 아래에서도 짙은 막대가 그대로 밝아 보였음). 화살표 키·Home·End로도 탭을 옮깁니다. 앱 버전은 메뉴의 앱 정보에만 나옵니다(v29부터 기록 화면과 코스 선택에서 뺐습니다. 만드는 사람의 표시라 쓰는 사람에게는 소음이었습니다). 새로고침하면 기록 화면으로 엽니다. 버전마다 바뀐 점은 [docs/IMPROVEMENTS.md](docs/IMPROVEMENTS.md)에 쌓습니다.
- 기록 화면(지금 치는 홀만)
  - 배경에 이 앱이 직접 그린 지금 홀이 깔립니다. Par 3은 티에서 그린까지 넘기는 홀, Par 4·5는 페어웨이입니다. 홀마다 핀과 그린 모양(v33부터 페어웨이 가장자리도)이 바뀌고, 홀 설명에 도그렉이 있으면 그쪽으로 휘며, 아일랜드 홀이면 그린 둘레에 물을 그립니다. 골프장이나 앱의 홀 이미지는 가져오지 않습니다.
  - 홀 전체가 보이는 띠 안에 들어옵니다(v33). 띠는 칩 줄 아래에서 카드 위까지, 카드 폭만큼입니다. 홀을 가로로 눕혀 티는 왼쪽, 그린은 오른쪽, 플레이어의 왼쪽은 위(머리줄의 작은 홀 그림과 같은 방향)에 두고, 티·그린과 프린지·페어웨이·벙커와 홀 설명이 말한 물·깃발이 띠 안에 다 들어오는 가장 큰 한 축척으로 그려 띠 가운데에 둡니다. 직접 그린 홀의 그린은 실제 크기(32×26 m 정도, 아주 짧은 띠에서는 18×14px 이상), OSM 홀은 지도의 그린 그대로이고, 100 m·150 m 표시는 코스의 거리 말뚝처럼 그린 중앙까지 경기선을 따라 잰 자리에 있습니다. 홀 안내에 "그림의 100 m·150 m 표시는 그린 중앙까지의 거리예요."가 함께 나옵니다. 표시의 숫자 알약은 둘 다 경기선의 같은 쪽(되도록 위)에, 각자 점 위 가운데나 둘이 닿을 때는 서로 바깥쪽으로 기울여 두고, 깃발·그린·티와 겹치지 않을 때만 나옵니다. 그림은 칩 줄에서 6px 넘게 떨어집니다. 직접 그린 홀의 티는 16×10px보다 작아지지 않고, OSM 홀에서 경기선이 시작하는 뒤 티만 그린 색이고 나머지 티는 페어웨이 색으로 물러납니다(v33 비평 뒤). 띠가 50px보다 낮으면(360×640, 375×667의 상세, 375×553) 홀을 띠에 맞추지 않습니다. 칩 줄 맨 앞에 작은 홀 그림이 나오고, 뒤의 그림은 v31처럼 머리줄 뒤에 세로로 40%로 물립니다. 이 전환은 화면 키가 아니라 그림을 그릴 때 잰 띠로 합니다. 50px 아래에서는 홀을 맞출 칸이 42px도 안 되어 OSM 그린의 절반이 15px보다 작고 거리 표시가 거의 들어가지 않았습니다(비평 권고, 상위 세션 결정). v31까지는 티를 다음 홀 뒤에, 그린을 띠 안에 세로로 그려 카드가 티와 티샷 앞 연못을 가리고, 그린 뒤 벙커가 칩 밑에 들었습니다.
  - 에버리스 골프리조트는 OpenStreetMap(OSM) 지도 데이터로 실제 홀 모양을 그립니다(v27). 27홀 중 OSM의 티·그린·페어웨이를 공식 Par·거리·홀 설명과 맞춘 25홀이고, 레이크 4·5번은 맞출 근거가 모자라 위의 그림 그대로입니다. 그 홀의 그린 두 개, 티들, 페어웨이, 벙커, 가까운 물을 같은 평면도(평평한 색과 가장자리 선, v31)로 그리고, 위의 띠에 홀 전체를 한 축척으로 맞춥니다(v33). 저작권 링크를 누르는 자리 옆(오른쪽이나 위) 중 홀이 가장 크게 들어가는 쪽에 두고, 물은 홀을 둘러싼 배경이라 띠 가장자리에서 잘립니다. 깃발은 경기선에 가까운 그린에 꽂습니다. 100 m·150 m 표시는 실제 경기선(뒤 티에서 페어웨이 가운데를 지나 두 그린 가운데까지)을 따라 그린 중앙에서 잰 자리입니다. v27–v31은 티가 아래(다음 홀 뒤), 그린이 위가 되게 세로로 그렸습니다.
  - OSM 그림이 보이는 동안 카드 6px 위에 "© OpenStreetMap" 링크가 있습니다. v33부터 배지가 아니라 회색 글자(13px, 보통 굵기)만이고, 글자의 왼쪽 끝은 카드의 안쪽 가장자리(첫 캡슐의 왼쪽)에 맞습니다. 홀은 이 모서리를 비워 두어 글자 뒤가 러프입니다(러프 위 5.3:1). 회색 글자는 물 위에서 읽히지 않으므로(흰색도 4.1:1) 물이 그 뒤에 오면 홀을 칸 안의 여유만큼 옮기고, 그래도 남으면 링크를 반대쪽 끝, 카드의 오른쪽 안쪽 가장자리(오른쪽 끝이 마지막 캡슐의 오른쪽에 맞음)에 둡니다. 에버리스 25홀 × 홀을 맞추는 잰 띠 4개(100곳) 중 99곳에서 글자 뒤에 물이 없고, 390×844 상세의 새별 7만 글자 줄 상자의 0.1%(모서리)에 물이 남습니다. OSM 저작권 페이지를 새 탭에서 열고 리퍼러를 보내지 않으며, 누르는 자리는 28–40px입니다. 홀 안내에는 "그림은 OpenStreetMap 지도 데이터로 그린 실제 홀 모양이에요. © OpenStreetMap 기여자"가, 앱 정보에는 OSM으로 그린다는 것과 ODbL이 나옵니다. 홀과 거리 표시는 이 링크를 누르는 자리(글자와 둘레)에서 4px 넘게 떨어집니다. 칩 줄(과 그 아래 안내 띠) 밑에서 카드까지 50px가 안 되는 화면(360×640, 375×667의 상세, 375×553)에서는 홀을 맞추지 않으므로 직접 그린 그림을 쓰고 링크도 없습니다.
  - 벙커와 물(v22)은 홀 설명(공식 홀 안내를 짧게 다시 쓴 구절)이 이름 붙인 곳에만, 그 말이 가리키는 대략 위치에 그립니다. 그린 앞·뒤·좌·우·주변, 페어웨이 좌·우·양쪽, 티 앞 물이고, 자리 없이 "좌측 벙커"처럼 쪽만 말하면 Par 4·5는 페어웨이, Par 3은 그린 옆입니다. 위치가 분명하지 않은 구절(그린 옆, 페어웨이 가로지르는 벙커 등), 그라스 벙커, 물인지 알 수 없는 "해저드", 두 그린 중 한 곳의 벙커는 그리지 않습니다. 그림은 홀 모양을 바꾸지 않고 그린·깃발·티와 서로를 가리지 않으며, v33부터 홀 설명이 말한 벙커·물은 다 보이는 띠 안에 둡니다(자리가 없으면 홀을 조금씩, 네 번까지 작게 그립니다). 홀 안내에 "그림은 Par와 거리로 그린 대략적인 모양이에요. 벙커·물은 공식 홀 안내 문구로 그린 대략 위치예요."가 함께 나오고(v31부터 벙커·물이 없는 홀도 앞 문장은 늘), 실제 모양은 공식 홀 안내 링크에서 봅니다.
  - 그림은 야디지북의 평면도처럼 평평합니다(v31). 러프, 페어웨이, 그린과 티, 모래, 물을 팔레트의 한 색씩으로 칠하고, 페어웨이의 퍼스트 컷과 그린의 프린지는 같은 짙은 초록 선 하나로 그립니다. 물가와 깃대에는 짙은 선을 둘러 어느 바닥에서도 보이게 합니다(물은 페어웨이 위에서 1.26:1, 흰 깃대는 그린 위에서 2.1:1이었음). 그린·벙커·연못은 둥근 모양입니다(전에는 끝이 뾰족한 잎이나 레몬처럼 보였음). 깃발은 흰 깃대와 빨간 삼각기, 컵입니다. v22부터 v30까지의 빛(밝은 쪽과 그늘), 깎은 줄, 노이즈 결, 볼록한 그린과 그림자, 벙커의 턱, 물의 깊이와 반사, 가장자리의 어둠, 위쪽 그늘은 모두 뺐습니다. 게임 그림처럼 보였고, v30부터 그림 위의 카드와 칩이 불투명해 그림이 앞에 나설 이유가 없기 때문입니다. 그래서 그림 안에는 그라디언트·패턴·마스크·클립 경로·필터가 하나도 없고(e2e가 확인), 칠하는 색은 10가지 이하입니다.

  - 백업 파일에 진행 중이던 라운드가 있으면 지금 라운드를 바꿀지 먼저 묻습니다. 확인하면 지금 라운드를(끝낸 홀이 있으면) 지난 라운드에 보관한 뒤 바꾸고, 취소하면 백업의 라운드를 지난 라운드에 넣습니다.

  - 거리: 골프장이 밝힌 티 이름과 단위(m·yd)대로 티마다 하나씩 넣습니다. 두 단위가 다 있으면 m를 씁니다. 티 이름 없이 길이 하나만 적은 곳(에버리스 등)은 그 길이 하나만 둡니다. 화이트(없으면 레귤러·블루·프런트) 티가 맨 앞이고 나머지는 정해진 티 순서입니다. 그린이 둘인 홀은 A·B 또는 좌·우 그린별로 두고 같은 티끼리 붙여 둡니다. 숫자로만 이름 붙인 티(남촌의 71·67·…)는 큰 숫자부터입니다. Par에 맞지 않는 길이(Par 3은 60–280m, Par 4는 180–560m, Par 5는 300–650m 밖)와, 모든 티가 같은 길이로 적힌 홀(공사 중 표시)은 뺍니다.
  - 거리가 없는 곳: 같은 숫자를 페이지마다 m와 yd로 다르게 적은 사이프러스, 스코어카드에 단위가 없는 안성(다른 페이지의 합계로 야드라고 짐작만 됨), 단위를 적지 않은 곳(신안 토마토, 설악썬밸리, 경상권 9홀 코스 23개), 조사 자료가 공식 페이지끼리 거리가 맞지 않는다고 적은 경상권 9홀 코스 15개(합계가 안 맞는 줄, 티 순서가 뒤바뀐 칸, m·yd 환산 불일치 등).
  - 홀 설명: 공식 안내를 보고 짧게 다시 쓴 구절(도그렉 방향, 해저드·벙커 위치 등) 3개 이하, 40자 이하입니다. 안내문을 옮겨 적지 않습니다. 도그렉 구절은 먼저 남겨, 그려지는 홀이 그쪽으로 휩니다. 벙커·물 구절은 그림의 벙커·물이 됩니다(v22). 경상권은 조사 자료에 홀 설명이 없습니다.
  - 링크: 공식 사이트의 https 페이지만 둡니다. http로만 열리는 테디밸리·더클래식·예미지·서경타니 안내는 링크하지 않습니다.
  - 핸디캡(S.I.): 골프장이 적은 그대로, 9홀 안에서 1–9가 한 번씩이거나 다른 9홀과 합쳐 1–18이 한 번씩일 때만 넣습니다. 값이 겹치거나 빠진 9홀(40개)은 그 9홀 전체를 뺍니다.

### 홀 모양(OpenStreetMap, v27)

에버리스 골프리조트의 홀 모양은 OpenStreetMap에서 왔습니다(© OpenStreetMap 기여자, ODbL 1.0). 공식 코스 데이터와 섞지 않고 `src/data/osm/`에 따로 두며, 그 폴더의 README에 라이선스, 쿼리, 데이터 날짜(OSM 2026-11-20)가 있습니다.

- `src/data/osm/everis-holes.json`: 사람이 맞춘 홀 대응표입니다. 홀마다 OSM의 티·그린·페어웨이 id와 근거(공식 Par와 거리 대비 잰 길이, 앞 홀 그린에서 다음 홀 티까지 거리, 홀 설명과 맞는 물·벙커, OSM에 함께 그려 넣은 묶음)를 적었습니다. 세 9홀 모두 클럽하우스 근처(95–160m)에서 시작하고 끝나며, 홀이 땅 위에서 차례로 이어지고(그린에서 다음 티까지 52–102m), 그 순서의 Par가 공식 스코어카드와 홀마다 같습니다.
- 맞춘 25홀은 뒤 티에서 그린 가운데까지 경기선 길이가 공식 거리와 −6.9%~+4.4% 안에서 맞습니다(가장 큰 차이는 새별 8번, OSM에 더 뒤의 티가 없음). 새별 5번의 두 그린은 OSM이 `golf=tee`로 달았지만 넓이(512–540㎡, 이 코스 그린 421–638㎡, 티 59–122㎡)와 자리(홀 끝, 벙커가 둘러쌈)로 그린으로 그립니다. 레이크 4번(OSM에 그린이 없고 그 자리가 공사 중으로 그려짐)과 5번(가장 가까운 그린까지 374m로 공식 456m와 −18%, 그린 묶음이 둘)은 맞추지 않았습니다.
- `src/data/osm/everis.json`: 홀마다 경기선, 단순하게 줄인 그린·티·페어웨이·벙커·가까운 물(섬은 구멍) 윤곽을 그린 가운데 기준 동·북 m(소수 첫째 자리)로, 쓴 OSM 요소 id와 함께 둡니다. 77.9KB(gzip 29KB)이고, 빌드에서 따로 나뉜 파일이 되어 에버리스를 처음 그릴 때 같은 출처에서 불러옵니다(오프라인 캐시에 포함, 다른 코스는 받지 않음).
- 갱신: README의 쿼리로 Overpass 응답을 저장소 밖에 저장한 뒤 그 파일을 넘깁니다. 손으로만 돌리고 빌드·CI는 부르지 않습니다. 홀마다 잰 길이를 공식 거리 옆에 출력합니다.

```sh
npm run osm:holes -- <Overpass 응답>.json
```

## 오프라인

골프장처럼 신호가 약한 곳에서도 쓸 수 있게, 한 번 열고 나면 인터넷 없이 다시 열고 기록할 수 있습니다.

- 빌드할 때 `vite.config.ts`의 작은 플러그인이 `dist/sw.js`(서비스 워커)를 만듭니다. 빌드된 파일 전체(`index.html`, `assets/*`(스크립트, 스타일, 글꼴 세 파일, 글꼴과 아이콘의 라이선스), 아이콘, manifest) 목록과 파일 내용 해시로 만든 빌드 ID가 들어갑니다.
- 처음 열 때 이 파일들을 브라우저의 Cache Storage(`fairway-note-<빌드 ID>`)에 받아 두고, 그다음부터는 캐시에서 먼저 엽니다. 받을 때 HTTP 캐시를 건너뛰어 배포가 섞이지 않게 합니다. 받는 양은 14개 파일 약 1.59MB(글꼴 0.81MB, 에버리스 홀 모양 0.08MB 포함, gzip으로 약 1.06MB)입니다(v27). v25에는 13개 파일 약 1.50MB, 글꼴을 넣기 전(v21)에는 8개 파일 약 0.66MB였습니다.
- 새 버전이 배포되면 바로 바꾸지 않고, 화면 아래쪽 막대들 위에 "새 버전이 있습니다 · 다시 열기" 버튼을 띄웁니다. 기록을 방해하지 않으며, 누르면 새 버전으로 다시 엽니다. 라운드와 지난 라운드는 localStorage에 있으므로 그대로 남습니다.
- 새 버전이 자리를 잡으면 이 도구의 예전 캐시만 지웁니다.
- `npm run dev`에서는 서비스 워커를 등록하지 않습니다. 확인은 `npm run build && npm run preview`로 합니다. 서비스 워커는 `localhost`·`127.0.0.1`이나 HTTPS에서만 동작합니다.

## 개인정보 경계

결과 보내기를 누를 때만, 사용자가 고른 메일 앱이나 공유 대상으로 라운드 내용이 넘어갑니다. 앱이 스스로 보내는 요청은 없습니다. "공식 홀 안내" 링크와 "© OpenStreetMap" 출처 링크(v27)는 누를 때만 새 탭에서 열리고 리퍼러를 보내지 않습니다. 에버리스의 홀 모양은 앱에 묶여 있어 지도 서버에 요청하지 않습니다.

요약의 공유 이미지는 이 브라우저 안에서 캔버스로 그립니다(앱에 묶인 글꼴로, 내려받는 것 없음). 공유를 누를 때만 공유 시트로 넘기고, 이미지 저장을 누를 때만 내려받습니다. 그린 이미지는 어디에도 저장하지 않고 요약을 닫으면 버립니다.

백업 파일은 사용자가 내려받은 곳(다운로드 폴더, 파일 앱)이나 직접 고른 공유 대상에만 있습니다. 앱은 파일을 어디로도 보내지 않고, 가져오기는 고른 파일을 이 브라우저 안에서만 읽습니다. 파일 형식은 `{ app: "fairway-note", format: 1, exportedAt, current, history }`이고(`current`는 지금 라운드, 입력이 없으면 `null`, `history`는 지난 라운드 배열), 라운드 기록 말고는 기기·계정 정보가 없습니다. 열어 볼 수 있는 JSON이니 다른 사람에게 보내지 않도록 주의하세요.

입력한 라운드는 이 브라우저의 localStorage(`fairway-note:round:v1`) 한 곳에만 저장해 새로고침이나 화면 꺼짐 뒤에도 이어서 기록할 수 있게 합니다. 페이지를 열기만 해서는 저장하지 않고 코스를 고르거나 첫 입력을 할 때 저장합니다. 마지막으로 고른 코스(골프장·9홀 id, 직접 입력한 이름)는 `fairway-note:prefs:v1`에 따로 둡니다. 첫 저장 때 브라우저에 저장소를 지우지 말라고(`navigator.storage.persist()`) 한 번 요청합니다.

말로 입력(v21, 처음에는 꺼짐)은 키보드가 글자 칸에 넣은 글자만 읽습니다. 이 앱은 마이크를 쓰지 않고 마이크 권한도 묻지 않으며, 브라우저의 음성 인식(Web Speech)도 쓰지 않습니다. CSP도 그대로입니다. 받아쓰기는 키보드가 합니다. iPhone은 받아쓰기를 기기 안에서 처리하고, Android는 키보드에 따라 음성을 서버로 보낼 수 있습니다. 이것은 이 앱이 아니라 키보드가 정하는 일이고, 시트에 그렇게 적어 두었습니다. 읽은 줄은 이 브라우저 안의 작은 해석기(`src/voice-commands.ts`)가 명령으로 바꾸고 바로 버립니다. 줄은 저장하거나 보내지 않습니다. 글자 칸은 검색 칸이 아닌 일반 칸(`type="text"`, `autocomplete="off"`)이라 받아쓴 말이 검색으로 넘어가거나 브라우저에 남지 않습니다. 저장되는 것은 켬 하나(`fairway-note:prefs:v1`의 `voice: true`)뿐입니다.

해저드 수는 홀마다 `hazard`로, 벙커 수(v14, 타수에 넣지 않음)는 `bunker`로 저장합니다. 라운드 마치기를 누른 라운드에는 `closed: true`가 붙어 마지막 홀 칩인이 끝낸 홀로 남습니다. 해저드·벙커가 생기기 전에 저장된 라운드는 0으로 읽고 따로 보관할 것도 없습니다(`version: 1` 유지). 이전 버전 앱은 이 값을 모르므로 그 홀을 해저드 벌타 없이 보여 주고, 그 앱에서 저장하면 해저드 수가 빠집니다(샷 세부와 같은 방식). 샷 세부는 같은 키의 홀마다 선택 항목(`tags`, `obByTag`)으로 저장합니다. 세부 일부를 읽을 수 없으면(모르는 칩 값 등) 타수는 그대로 두고 그 세부만 빼고 불러오며, 원래 값은 아래처럼 따로 보관합니다. 저장된 값이 깨졌거나 더 새 버전이 쓴 값이라 읽을 수 없으면 덮어쓰기 전에 `fairway-note:corrupt:<시각>` 키로 따로 보관합니다(최근 3개까지). 보관할 수 없으면 저장하지 않습니다. 새 라운드를 시작하면 바꿉니다(끝낸 홀이 있으면 먼저 지난 라운드에 보관합니다). 지난 라운드는 같은 localStorage의 다른 키 `fairway-note:history:v1`에 `{ id, endedAt, round }` 배열로 저장하고, 라운드마다 지금 라운드와 같은 검사(코스·해저드·샷 세부 포함)를 거칩니다. 첫 라운드를 보관할 때 생기고 마지막 라운드를 지우면 없어집니다. 저장된 지난 라운드를 일부라도 읽을 수 없으면(깨진 값, 모르는 필드나 세부) 덮어쓰기 전에 같은 `fairway-note:corrupt:<시각>` 키에 따로 보관하고(지금 라운드의 보관본과 합쳐 최근 3개), 보관할 수 없으면 지난 라운드를 바꾸지 않습니다. 서버로 보내지 않고, sessionStorage·IndexedDB·쿠키는 쓰지 않습니다. Cache Storage에는 앱 파일만 두고 라운드 내용은 넣지 않습니다. 저장할 수 없는 환경(일부 개인정보 보호 모드)에서는 기록 화면에 그렇게 알리고 메모리에서만 동작합니다.

CSP 메타 태그가 네트워크 연결(`connect-src 'none'`)과 다른 출처의 스크립트·스타일·이미지·글꼴, 인라인 스타일 태그를 막습니다. 글꼴은 앱과 같은 출처의 파일만 쓰고 외부 글꼴 서비스에 요청하지 않습니다. 그래서 `npm run dev`에서는 Vite가 넣는 스타일도 막히니 화면 확인은 `npm run build && npm run preview`로 합니다.
