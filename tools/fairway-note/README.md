# Fairway Note — 골프 스코어 노트

라운드 중 휴대폰으로 홀마다 드라이버·어프로치·퍼터 스윙을 한 번씩 눌러 세고, OB·해저드 벌타와 멀리건을 함께 표시하는 정적 웹 앱입니다. 기록 화면에는 지금 치는 홀만 보이고, 합계·스코어카드·분석은 스코어카드 화면에 모았습니다. 끝낸 라운드는 지난 라운드로 보관해 추세를 보고, 백업 파일로 다른 기기에 옮길 수 있습니다. TypeScript + Vite로 만들었고 런타임 의존성, 백엔드, 계정, 분석 도구가 없습니다.

## 실행

Node.js 22.12 이상이 필요합니다.

```sh
npm ci
npm run dev
```

배포 빌드 확인:

```sh
npm run build
npm run preview -- --port 4175 --strictPort
```

주소: http://127.0.0.1:4175

CSP 때문에 `npm run dev`에서는 자동 새로고침(HMR)과 Vite가 넣는 스타일이 막힙니다. 화면은 빌드 후 미리보기로 확인합니다.

## 기능과 제한

- 코스 선택(첫 화면 "어디서 치세요?"): 러프색 바탕에 검색 칸, 지역 칩, 흰 카드 목록이 있고, 고른 코스는 아래 시트에서 전반·후반을 고르고 시작합니다. 열 때 코스 선택 화면이 먼저 나옵니다. 저장된 라운드가 없을 때, 예전 버전이 아무것도 기록하지 않은 채 저장해 둔 라운드만 있을 때, 다른 날 기록하던 라운드가 남아 있을 때입니다. "새 라운드 시작"을 누를 때도 열립니다. 코스 선택은 탭 막대의 홈까지 가리므로, 첫 실행에는 제목 오른쪽(다른 때 취소가 있는 자리)에 사이트로 돌아가는 `carpenta.github.io` 링크가 있습니다.
  - 지난번에 고른 코스와 전·후반 9홀이 미리 골라져 있어 "이 코스로 시작" 한 번으로 시작합니다. 처음에는 에버리스 골프리조트 새별(전반)·레이크(후반)입니다. 고른 코스는 `fairway-note:prefs:v1`에 기억합니다.
  - 골프장 이름, 초성(예: `ㅇㅂㄹㅅ`), 지역으로 찾고, 지역 칩(제주·수도권·강원·충청·전라·경상)으로 좁힙니다.
  - 9홀 코스가 셋 이상인 골프장은 전반·후반을 고르고, 둘인 골프장은 바로 정해지며 "전·후반 바꾸기"로 순서만 바꿉니다. 9홀짜리는 두 번 돕니다.
  - 코스 이름 줄의 18홀/9홀에서 9홀을 고르면 후반이 없어지고 그 줄 이름이 "코스"가 됩니다. 라운드·홀 목록·진행 막대·스코어카드·요약이 9홀로 움직이고, 지난 라운드와 보고서에는 "에버리스 골프리조트 새별 9홀"처럼 남습니다. 고른 홀 수도 다음 라운드를 위해 기억합니다. 코스 바꾸기에서는 라운드의 홀 수를 바꾸지 않습니다.
  - 처음 화면에서 저장된 라운드나 지난 라운드를 읽을 수 없을 때, 또는 홈 화면 앱인데 기록이 하나도 없을 때(브라우저가 정리했을 수 있음) 코스 목록 위에 안내 카드가 나옵니다. "백업 파일에서 복원"은 메뉴의 백업 가져오기와 같고, 결과를 카드에 보여 주며, 진행 중이던 라운드를 되살리면 그 라운드로 바로 갑니다.
  - 목록에 없는 골프장은 "직접 입력"으로 이름을 넣고 모든 홀 Par 4로 시작합니다.
  - "새 라운드 시작"에서 코스 선택을 취소하면 지금 라운드가 그대로 남습니다.
- 화면은 세 개(스코어카드, 기록, 지난 라운드)이고 화면 아래 짙은 탭으로 옮깁니다. 탭 막대는 같은 폭의 네 칸으로, 맨 왼쪽 "홈"(집 아이콘과 이름)이 사이트로 돌아가는 링크이고 나머지가 세 탭입니다. 화살표 키·Home·End로도 탭을 옮깁니다. 앱 버전(v18)은 기록 화면 카드 오른쪽 끝 바로 위(작은 어두운 알약), 코스 선택 화면 위쪽, 메뉴의 앱 정보에 작게 나옵니다. 새로고침하면 기록 화면으로 엽니다. 버전마다 바뀐 점은 [docs/IMPROVEMENTS.md](docs/IMPROVEMENTS.md)에 쌓습니다.
- 기록 화면(지금 치는 홀만)
  - 배경에 이 앱이 직접 그린 지금 홀이 깔립니다. 아래가 티, 위가 그린과 깃발이고, Par 3은 가까운 큰 그린, Par 4·5는 페어웨이입니다. 홀마다 핀과 그린 모양이 바뀌고, 홀 설명에 도그렉이 있으면 그쪽으로 휘며, 아일랜드 홀이면 그린 둘레에 물을 그립니다(그 밖에는 물·벙커를 그리지 않습니다). 골프장이나 앱의 홀 이미지는 가져오지 않습니다.
  - 위쪽 첫 줄: 메뉴, 화면 가운데의 ‹ "N번 홀" › 홀 이동, 오른쪽 칸의 점수 배지. 둘째 줄은 고정 배치로, 왼쪽에 Par·거리·HDCP 알약, 오른쪽 끝에 끝낸 홀이 있으면 진행 알약 "7홀까지 +3"(언더파는 빨강)과 "홀 안내" 칩이 있어 HDCP가 생기거나 빠져도 움직이지 않습니다. 홀 안내를 누르면 홀 설명 구절(예: 내리막 · 블라인드 티샷)과 "공식 홀 안내 보기 ↗"(새 탭)가 나옵니다. 자리가 모자라면 HDCP, 그다음 거리가 알약에서 빠지고 홀 안내에만 남습니다. 홀 번호 아래에는 18칸 진행 막대(끝낸 홀, 건너뛴 홀은 모래색, 지금 홀)가 늘 보입니다. 홀 번호를 누르면 18칸 홀 목록이 열려 홀마다 타수와 표시, 전반·후반 합이 보이고, 누른 홀로 갑니다. 지나온 홀 중 기록하지 않은 홀은 모래색 점선 칸으로 보입니다. 첫 라운드 1번 홀에서는 누르기 전에 한 번만 "숫자를 길게 누르면 바로 골라요" 안내가 나옵니다(본 것은 `fairway-note:prefs:v1`에 기억). 알약 숫자 크기도 알약 높이에 맞춰 줄어 +/− 버튼과 늘 8px 이상 떨어집니다.
  - 위 막대 오른쪽 칸의 원형 배지(60px, 카드와 겹치지 않음): 첫 탭 전에는 옅은 테두리의 흰 원에 "Par"와 그 홀의 Par가 보이고, 그다음은 드라이버 + 어프로치 + 퍼터 + OB + 해저드로 계산한 홀 타수와 스코어카드 표시(이글 이하 ◎, 버디 ○, 파는 표시 없음, 보기 □, 더블 보기 이상 ⧈), 이름(파·보기·홀인원 등). 언더파는 빨강, 파는 터프색입니다. 버디 이상이 되면 표시가 한 번 그려지고 배지가 울립니다(움직임 줄이기 설정에서는 없음).
  - 드라이버(Par 3에서는 "티샷") · 어프로치 · 퍼터 알약: 위의 + 로 한 번에 한 타, 아래의 − 로 하나 뺍니다. 한 항목은 0–15까지 셉니다. 드라이버는 티샷(OB 뒤 다시 친 티샷 포함), 어프로치는 두 번째 샷부터 그린 전까지, 퍼터는 그린 위 퍼트입니다.
  - OB(흰 말뚝)와 해저드(빨간 말뚝): 누를 때마다 1벌타가 타수에 더해지고 개수가 표시됩니다. 벌타 줄은 알약 세 칸에 맞춰 OB는 드라이버 아래, 해저드는 퍼터 아래에 있고, 가운데(어프로치 아래)는 기본에서 "빼기"(마지막에 더한 벌타를 하나 뺌, 뺄 것이 있을 때만), 상세에서 벙커(벙커에 들어간 횟수, 타수에 넣지 않음)입니다. 벌타·벙커를 길게 누르면(0.5초) 클럽과 같은 0–5+ 고르기가 열립니다.
  - +·−·벌타를 누르면 4초 동안 "드라이버 +1 · 되돌리기" 안내가 시트 위쪽 클럽 이름 위에 뜹니다. 되돌리기를 누르면 그 홀이 누르기 전으로 돌아갑니다. 안내는 어떤 버튼도 가리지 않고, 홀을 옮기면 사라집니다. 아무것도 적지 않은 홀에서 다음 홀을 누르면 같은 자리에 "n번 홀은 비워 두고 넘어갑니다"와 되돌리기(그 홀로 돌아감)가 뜹니다.
  - 기본 / 상세: 상세에서는 알약이 줄고, 티샷 한 줄(결과, 김·짧음, 미스샷)과 다섯 방향 한 줄(많이 좌, 좌, 페어웨이, 우, 많이 우), 벌타 줄에 벙커가 더해집니다. 미스샷은 누를 때마다 헛스윙 → 뒤땅/토핑 → 없음으로 바뀝니다. 고른 결과는 첫 드라이버 샷의 세부로 저장되고, 드라이버가 0이면 티샷을 하나 셉니다. 같은 것을 다시 누르면 지웁니다. Par 3에서는 가운데가 "온그린"입니다.
  - "다음 홀"은 아래 탭 바로 위에 있고, 마지막 홀에서는 "라운드 마치기"(라운드 요약)가 됩니다. 숫자를 길게 누르면(0.5초) 0, 1, 2, 3, 4, 5+ 중에서 바로 고르고, 되돌리기로 되돌릴 수 있습니다. ‹ ›와 다음 홀은 이동만 하고 아무것도 기록하지 않습니다. 기록 화면을 옆으로 밀어도 앞뒤 홀로 가고, 시트가 그쪽으로 미끄러집니다. 버튼 위에서 시작한 밀기는 그 버튼을 누르지 않습니다. 시트만 움직이고 점수 배지와 칩은 그대로 있습니다.
  - 메뉴(아래에서 올라오는 시트, 항목을 누르면 그 자리에 펼쳐짐): 새 라운드(무슨 일이 생기는지 보여 주고 "새 라운드 시작" → 코스 선택), 코스 바꾸기(기록한 타수는 두고 코스와 홀마다 Par를 고른 코스의 공식 값으로), 결과 보내기(이메일·공유), 백업과 복원, 이 홀 멀리건(표시만, 타수에 넣지 않음), 큰 글씨(숫자와 글씨를 약 1.15배로, 켜 두면 다음에도 유지), 앱 정보(우리의 약속: 계정·광고·구독 없음, 기록은 이 기기에만, 신호 없이도 기록, 라운드 중 팝업 없음. 쓰는 법과 버전).
  - 375×553(Safari 막대를 뺀 iPhone SE)과 375×667에서 기본 화면과 상세가 모두 스크롤 없이 들어옵니다. 600px 아래 화면에서는 그림 띠 대신 칩 줄 맨 앞에 작은 홀 그림(티는 왼쪽, 그린은 오른쪽, 도그렉은 위·아래로)이 나옵니다. 700px 아래 화면의 상세는 클럽 이름 대신 숫자 옆에 작은 클럽 아이콘을 두고, 600px 아래에서는 칩 줄 대신 홀 번호 아래에 Par·거리를 쓰고 벌타를 같은 폭의 알약 한 줄로 줄입니다. 기본/상세 전환은 44px 높이입니다. 알약 숫자는 +/− 버튼과 8px 이상 떨어지고, 버튼은 48px 이상입니다.
- 샷 세부(클럽 상세): 알약 가운데 숫자(+와 − 사이)를 짧게 누르면 그 클럽의 작은 패널이 열리고, 이 홀에서 친 그 클럽의 샷마다 세부를 칩 하나로 고릅니다.
  - 칩: 드라이버(좌·페어웨이·우, 김·짧음, 많이 좌·헛스윙·많이 우, 좌 OB·뒤땅/토핑·우 OB), 어프로치(좌·온그린·우, 김·짧음, 벙커·해저드·헛스윙), 퍼터(좌·들어감·우, 김·짧음). 왼쪽으로 간 것은 왼쪽 칸, 오른쪽은 오른쪽 칸, 목표는 가운데이고, 방향 칩에는 상세 패드와 같은 화살표가 있습니다. Par 3의 티샷은 가운데가 "온그린"입니다.
  - 마지막 샷이 먼저 골라져 있고, 두 번 이상 쳤으면 위의 숫자 줄(1, 2, …)에서 샷을 고릅니다(세부가 있는 샷에는 점). 칩 하나를 누르면 그 샷에 기록되고, 같은 칩을 다시 누르면 지웁니다. 아직 0타이면 칩을 고를 때 첫 샷을 함께 셉니다(상세 패드와 같음).
  - 닫기(×), 바깥 누르기, Esc로 닫고 숫자로 포커스가 돌아갑니다. 세부가 있는 클럽은 숫자 오른쪽 위에 작은 점이 붙습니다. +와 −는 그대로 한 번에 한 타이고, 숫자를 길게 누르면 예전처럼 0–5+ 고르기가 열립니다.
  - 패널은 카드 안쪽 가장자리(세 알약의 바깥쪽)에 맞춰 열리고, 칩은 한 격자에 놓이며 탭 막대 위에서 끝납니다.
  - 상세 패드는 첫 드라이버 샷의 세부를 기록합니다(패널의 드라이버 1번째 티샷과 같은 값). 좌 OB·우 OB 세부는 OB를 1 더하고(이미 센 OB가 있으면 더하지 않음), 지우면 그 1을 뺍니다. 해저드 칩은 기록만 하고 벌타는 해저드 말뚝으로 셉니다. 라이브 사이트(이전 버전)가 저장한 어프로치·퍼터 세부도 그대로 읽고 다시 저장합니다.
  - 세부가 있을 때만 분석에 "샷 세부"(칩별 수, 티샷 좌·우와 OB, 퍼트 짧음·김, 헛스윙 수)가 나오고, 이메일·공유 본문에 홀별 세부와 "[샷 세부]"가 붙습니다.
- 지금 치고 있는 홀은 퍼트를 넣기 전까지 "진행 중"으로 보이고 합계·스코어카드·분석에 넣지 않습니다(티샷만 친 홀이 이글로 잡히지 않게). 퍼트 없이 끝난 홀(칩인)은 다음 홀로 넘어가거나 라운드 마치기를 누르면 들어갑니다(마지막 홀 포함). 그 홀에 다시 기록하거나 다른 홀로 가면 다시 진행 중이 됩니다.

## 오프라인

골프장처럼 신호가 약한 곳에서도 쓸 수 있게, 한 번 열고 나면 인터넷 없이 다시 열고 기록할 수 있습니다.

- 빌드할 때 `vite.config.ts`의 작은 플러그인이 `dist/sw.js`(서비스 워커)를 만듭니다. 빌드된 파일 전체(`index.html`, `assets/*`, 아이콘, manifest) 목록과 파일 내용 해시로 만든 빌드 ID가 들어갑니다.
- 처음 열 때 이 파일들을 브라우저의 Cache Storage(`fairway-note-<빌드 ID>`)에 받아 두고, 그다음부터는 캐시에서 먼저 엽니다. 받을 때 HTTP 캐시를 건너뛰어 배포가 섞이지 않게 합니다.
- 새 버전이 배포되면 바로 바꾸지 않고, 화면 아래쪽 막대들 위에 "새 버전이 있습니다 · 다시 열기" 버튼을 띄웁니다. 기록을 방해하지 않으며, 누르면 새 버전으로 다시 엽니다. 라운드와 지난 라운드는 localStorage에 있으므로 그대로 남습니다.
- 새 버전이 자리를 잡으면 이 도구의 예전 캐시만 지웁니다.
- `npm run dev`에서는 서비스 워커를 등록하지 않습니다. 확인은 `npm run build && npm run preview`로 합니다. 서비스 워커는 `localhost`·`127.0.0.1`이나 HTTPS에서만 동작합니다.

## 개인정보 경계

결과 보내기를 누를 때만, 사용자가 고른 메일 앱이나 공유 대상으로 라운드 내용이 넘어갑니다. 앱이 스스로 보내는 요청은 없습니다. "공식 홀 안내" 링크는 누를 때만 새 탭에서 열리고 리퍼러를 보내지 않습니다.

요약의 공유 이미지는 이 브라우저 안에서 캔버스로 그립니다(시스템 글꼴만, 내려받는 것 없음). 공유를 누를 때만 공유 시트로 넘기고, 이미지 저장을 누를 때만 내려받습니다. 그린 이미지는 어디에도 저장하지 않고 요약을 닫으면 버립니다.

백업 파일은 사용자가 내려받은 곳(다운로드 폴더, 파일 앱)이나 직접 고른 공유 대상에만 있습니다. 앱은 파일을 어디로도 보내지 않고, 가져오기는 고른 파일을 이 브라우저 안에서만 읽습니다. 파일 형식은 `{ app: "fairway-note", format: 1, exportedAt, current, history }`이고(`current`는 지금 라운드, 입력이 없으면 `null`, `history`는 지난 라운드 배열), 라운드 기록 말고는 기기·계정 정보가 없습니다. 열어 볼 수 있는 JSON이니 다른 사람에게 보내지 않도록 주의하세요.

입력한 라운드는 이 브라우저의 localStorage(`fairway-note:round:v1`) 한 곳에만 저장해 새로고침이나 화면 꺼짐 뒤에도 이어서 기록할 수 있게 합니다. 페이지를 열기만 해서는 저장하지 않고 코스를 고르거나 첫 입력을 할 때 저장합니다. 마지막으로 고른 코스(골프장·9홀 id, 직접 입력한 이름)는 `fairway-note:prefs:v1`에 따로 둡니다. 첫 저장 때 브라우저에 저장소를 지우지 말라고(`navigator.storage.persist()`) 한 번 요청합니다.

해저드 수는 홀마다 `hazard`로, 벙커 수(v14, 타수에 넣지 않음)는 `bunker`로 저장합니다. 라운드 마치기를 누른 라운드에는 `closed: true`가 붙어 마지막 홀 칩인이 끝낸 홀로 남습니다. 해저드·벙커가 생기기 전에 저장된 라운드는 0으로 읽고 따로 보관할 것도 없습니다(`version: 1` 유지). 이전 버전 앱은 이 값을 모르므로 그 홀을 해저드 벌타 없이 보여 주고, 그 앱에서 저장하면 해저드 수가 빠집니다(샷 세부와 같은 방식). 샷 세부는 같은 키의 홀마다 선택 항목(`tags`, `obByTag`)으로 저장합니다. 세부 일부를 읽을 수 없으면(모르는 칩 값 등) 타수는 그대로 두고 그 세부만 빼고 불러오며, 원래 값은 아래처럼 따로 보관합니다. 저장된 값이 깨졌거나 더 새 버전이 쓴 값이라 읽을 수 없으면 덮어쓰기 전에 `fairway-note:corrupt:<시각>` 키로 따로 보관합니다(최근 3개까지). 보관할 수 없으면 저장하지 않습니다. 새 라운드를 시작하면 바꿉니다(끝낸 홀이 있으면 먼저 지난 라운드에 보관합니다). 지난 라운드는 같은 localStorage의 다른 키 `fairway-note:history:v1`에 `{ id, endedAt, round }` 배열로 저장하고, 라운드마다 지금 라운드와 같은 검사(코스·해저드·샷 세부 포함)를 거칩니다. 첫 라운드를 보관할 때 생기고 마지막 라운드를 지우면 없어집니다. 저장된 지난 라운드를 일부라도 읽을 수 없으면(깨진 값, 모르는 필드나 세부) 덮어쓰기 전에 같은 `fairway-note:corrupt:<시각>` 키에 따로 보관하고(지금 라운드의 보관본과 합쳐 최근 3개), 보관할 수 없으면 지난 라운드를 바꾸지 않습니다. 서버로 보내지 않고, sessionStorage·IndexedDB·쿠키는 쓰지 않습니다. Cache Storage에는 앱 파일만 두고 라운드 내용은 넣지 않습니다. 저장할 수 없는 환경(일부 개인정보 보호 모드)에서는 기록 화면에 그렇게 알리고 메모리에서만 동작합니다.

CSP 메타 태그가 네트워크 연결(`connect-src 'none'`)과 다른 출처의 스크립트·스타일·이미지, 인라인 스타일 태그를 막습니다. 그래서 `npm run dev`에서는 Vite가 넣는 스타일도 막히니 화면 확인은 `npm run build && npm run preview`로 합니다.
