# Fairway Note — 골프 스코어 노트

라운드 중 휴대폰으로 홀마다 드라이버·어프로치·퍼트 타수를 버튼으로 세고, OB와 멀리건을 함께 표시하는 정적 웹 앱입니다. 합계와 라운드 분석을 입력하는 즉시 보여 줍니다. 끝낸 라운드는 지난 라운드로 보관해 추세를 보고, 백업 파일로 다른 기기에 옮길 수 있습니다. TypeScript + Vite로 만들었고 런타임 의존성, 백엔드, 계정, 분석 도구가 없습니다.

## 실행

Node.js 22.12 이상이 필요합니다.

```sh
npm ci
npm run dev
```

배포 빌드 확인:

```sh
npm run build
npm run preview -- --port 4175 --strictPort
```

주소: http://127.0.0.1:4175

CSP 때문에 `npm run dev`에서는 자동 새로고침(HMR)과 Vite가 넣는 스타일이 막힙니다. 화면은 빌드 후 미리보기로 확인합니다.

## 기능과 제한

- 코스 선택: 열 때 코스 선택 화면이 먼저 나옵니다. 저장된 라운드가 없을 때, 예전 버전이 아무것도 기록하지 않은 채 저장해 둔 라운드만 있을 때, 다른 날 기록하던 라운드가 남아 있을 때입니다. "새 라운드 시작"을 누를 때도 열립니다.
  - 지난번에 고른 코스와 전·후반 9홀이 미리 골라져 있어 "이 코스로 시작" 한 번으로 시작합니다. 처음에는 에버리스 골프리조트 새별(전반)·레이크(후반)입니다. 고른 코스는 `fairway-note:prefs:v1`에 기억합니다.
  - 골프장 이름, 초성(예: `ㅇㅂㄹㅅ`), 지역으로 찾고, 지역 칩(제주·수도권·강원·충청·전라)으로 좁힙니다.
  - 9홀 코스가 셋 이상인 골프장은 전반·후반을 고르고, 둘인 골프장은 바로 정해지며 "전·후반 바꾸기"로 순서만 바꿉니다. 9홀짜리는 두 번 돕니다.
  - 목록에 없는 골프장은 "직접 입력"으로 이름을 넣고 모든 홀 Par 4로 시작합니다.
  - "새 라운드 시작"에서 코스 선택을 취소하면 지금 라운드가 그대로 남습니다.
- 18홀: 각 홀의 Par는 고른 코스의 공식 스코어카드 값으로 시작하고, 홀마다 Par 3·4·5로 고칠 수 있습니다. 고른 코스는 제목 아래, 보고서 제목·본문에 나오고, 스코어카드 아래에 Par 출처(공식 스코어카드 링크와 확인일)가 나옵니다.
- 코스를 고르기 전에 저장된 라운드는 에버리스 새별·레이크로 보고 저장된 Par를 그대로 씁니다.
- 홀마다 세는 항목
  - 드라이버: 티샷. OB 뒤 다시 친 티샷도 여기에 셉니다.
  - 어프로치: 두 번째 샷부터 그린에 올리기 전까지의 샷
  - 퍼터: 그린 위 퍼트
  - OB: 한 번에 1벌타가 타수에 더해집니다. 다시 친 샷은 드라이버나 어프로치로 따로 셉니다.
  - 멀리건: 표시만 하고 타수에 넣지 않습니다.
- 홀 타수 = 드라이버 + 어프로치 + 퍼터 + OB. 한 항목은 0–15까지 셀 수 있습니다.
- 샷 세부 기록(선택)
  - 드라이버·어프로치·퍼터의 + 를 누르면 타수는 그 한 번으로 바로 기록되고, 방금 친 샷의 세부 칩이 홀 제목·Par·타수 줄 자리에 겹쳐 나타납니다. 칩은 아무것도 밀어내지 않아 다음 + 는 같은 자리에 있고, 고르지 않아도 됩니다.
  - 드라이버: 페어웨이 · 좌 · 우 · 좌 OB · 우 OB · 헛스윙 · 뒤땅/토핑
  - 어프로치: 온그린 · 짧음 · 김 · 좌 · 우 · 벙커 · 해저드 · 헛스윙
  - 퍼터: 들어감 · 짧음 · 김 · 좌 · 우
  - 같은 칩을 다시 누르면 지웁니다. 좌 OB·우 OB를 고르면 OB가 1 더해지고, 지우면 그 1을 뺍니다. OB를 이미 직접 셌으면 더하지 않고(두 번 세지 않음), 좌·우를 바꿔도 그대로입니다.
  - 칩은 다른 항목을 누르거나, 홀을 옮기거나, 칩 사이 빈 곳을 누르거나, 6초가 지나면 닫힙니다(칩을 누를 때마다 6초를 다시 셉니다).
  - − 는 마지막 샷과 그 세부를 함께 지웁니다(그 세부가 더한 OB도).
  - 숫자를 누르면 그 항목의 마지막 샷 세부가 열리고, 다시 누를 때마다 앞의 샷으로 갑니다. 세부가 있는 항목은 숫자 아래에 점이 보입니다.
  - 세부가 있을 때만 분석에 "샷 세부"(칩별 수, 티샷 좌·우와 OB, 퍼트 짧음·김, 헛스윙 수)가 나오고, 이메일·공유 본문에 홀별 세부와 "[샷 세부]"가 붙습니다.
- 지금 치고 있는 홀은 퍼트를 넣기 전까지 "진행 중"으로 보이고 합계·스코어카드·분석에 넣지 않습니다(티샷만 친 홀이 이글로 잡히지 않게). 퍼트 없이 끝난 홀(칩인)은 다음 홀로 넘어가면 들어갑니다.
- 위쪽 합계(총타·Par 대비·기록한 홀·퍼트·OB·멀리건)는 화면을 내려도 따라옵니다.
- 스코어카드: 전반·후반 표와 OUT·IN·합계. 홀 번호를 누르면 그 홀로 갑니다.
- 라운드 분석(기록한 홀만 대상)
  - 평균 퍼트, 1퍼트·3퍼트 이상 홀 수
  - 그린 적중(GIR): 퍼트가 있고 드라이버 + 어프로치 + OB ≤ Par − 2인 홀
  - 스코어 분포(이글 이하 ~ 트리플 이상), Par별 평균, 가장 잘한·아쉬운 홀
  - 영역별 잃은 타수: 홀마다 티샷 1, 어프로치 Par − 3, 퍼트 2를 기준으로 더 친 타수와 OB 벌타. 기준보다 적게 친 홀이 다른 홀의 손실을 지우지 않습니다. 가장 많이 잃은 영역(같으면 모두)을 알려 줍니다.
- 결과 보내기
  - 이메일로 보내기: 휴대폰 메일 앱이 열리고 제목(코스·날짜·타수)과 본문(합계, 끝낸 홀별 타수, 분석)이 채워집니다. 받는 사람은 메일 앱에서 넣습니다. 이 앱이 메일을 직접 보내지는 않습니다(`mailto:` 링크).
  - 공유하기: 휴대폰 공유 시트(카카오톡·문자 등)로 같은 내용을 보냅니다. 공유 시트가 없는 브라우저에서는 "결과 복사"로 클립보드에 복사합니다.
- 지난 라운드
  - 새 라운드를 시작하면("새 라운드 시작", 지난 라운드 안내의 "새 라운드 시작", 다른 날 라운드를 열 때 먼저 나오는 코스 선택) 코스를 고른 순간, 끝낸 홀이 하나라도 있는 지금 라운드를 지난 라운드에 보관한 뒤 새로 시작합니다. 묻는 문구도 "지금 라운드를 지난 라운드에 보관하고 새로 시작할까요?"(다른 날 라운드는 "2026년 11월 18일 라운드를 …")입니다. 코스 선택을 취소하거나 "지난 라운드 이어서"를 누르면 보관하지 않고 그대로 이어서 기록합니다. 끝낸 홀이 없는 라운드는 보관하지 않고, 묻는 문구에 그렇게 적습니다. 같은 라운드는 두 번 보관하지 않습니다.
  - 보관하지 못하면(저장 공간 부족, 저장할 수 없는 브라우저) 그래도 지우고 새로 시작할지 한 번 더 묻습니다. 취소하고 백업 파일을 먼저 저장할 수 있습니다.
  - 화면 아래 "지난 라운드"에 최근 날짜부터 날짜, 코스, 타수와 Par 대비, 끝낸 홀 수, 퍼트(와 OB)가 나옵니다.
  - 추세: 라운드 수, 평균 타수와 Par 대비, 18홀 라운드가 6개 이상이면 최근 5라운드 평균, 라운드당 퍼트, 그린 적중률, 라운드당 OB, 최근 10라운드 타수 선. 평균은 18홀을 모두 끝낸 라운드로만 냅니다(9홀만 친 라운드가 평균을 낮추지 않게).
  - 라운드를 누르면 전체 화면에 그 라운드의 스코어카드와 분석이 읽기 전용으로 나오고, 이메일·공유로 보내거나 지울 수 있습니다(지우기 전에 묻습니다). 닫기 버튼이나 Esc로 닫습니다.
  - 목록은 보관·지우기·가져오기 때만 다시 그립니다. 탭으로 기록하는 속도는 그대로입니다.
- 백업 파일
  - "백업 파일 저장": 지난 라운드와 지금 라운드를 `fairway-note-backup-YYYY-MM-DD.json` 파일 하나로 내려받습니다. 파일 공유를 지원하는 브라우저에서는 "백업 파일 공유"로 메신저·메일·드라이브에 바로 보낼 수도 있습니다. 둘 다 인터넷 없이 됩니다.
  - "백업 파일 가져오기": 고른 파일의 라운드를 하나씩 검사해 지난 라운드에 더합니다. 이미 있는 라운드(같은 ID, 또는 같은 날짜에 홀 기록이 모두 같은 라운드)는 건너뛰고, 읽을 수 없는 라운드는 넣지 않고, 가져온·건너뛴·넣지 않은 개수를 알려 줍니다. Fairway Note 백업 파일이 아니면 아무것도 바꾸지 않고 그렇다고 알립니다.
  - 백업 파일에 진행 중이던 라운드가 있으면 지금 라운드를 바꿀지 먼저 묻습니다. 확인하면 지금 라운드를(끝낸 홀이 있으면) 지난 라운드에 보관한 뒤 바꾸고, 취소하면 백업의 라운드를 지난 라운드에 넣습니다.
  - 휴대폰을 바꾸거나 브라우저 데이터를 지우기 전에 저장해 두고, 새 기기에서 가져오면 됩니다.
- + 버튼에는 항목별 아이콘(드라이버 헤드, 아이언, 퍼터, OB 말뚝, 다시 치기)이 있습니다.
- 다른 날 기록하던 라운드가 남아 있으면 코스 선택이 먼저 열립니다. "지난 라운드 이어서"를 누르면 그 라운드를 이어서 기록하고, 새 코스로 시작하면 지난 기록을 지울지 한 번 더 묻습니다. 선택 화면을 닫으면 "이어서 기록 / 새 라운드 시작" 안내가 남습니다.
- 같은 브라우저의 다른 탭에서 기록하면 열려 있는 탭도 그 기록으로 바뀝니다.
- 휴대폰 화면
  - 이전·다음 홀 버튼은 화면 아래에 고정되어 엄지로 바로 누릅니다(홈 인디케이터 여백 포함).
  - 홀을 옮기면 홀 카드가 위쪽 합계 바로 아래로 와서, 375×553(Safari 막대를 뺀 iPhone SE 크기)에서도 Par 선택, 다섯 항목과 아래 버튼이 한 화면에 들어옵니다. 높이가 700px 이하인 화면에서는 위쪽 합계를 한 줄로 줄이고 항목 설명을 숨깁니다.
  - 햇빛 아래에서도 읽히도록 작은 글자(합계 이름, 홀 번호, 항목 설명, 스코어카드 행 이름)는 13px 이상, 흰 바탕 대비 4.5:1 이상입니다. 누를 수 있는 − 버튼은 초록 테두리로, 누를 수 없는 것은 흐리게 보입니다.
  - 라운드를 여는 동안 화면이 꺼지지 않게 Screen Wake Lock을 요청합니다. 다른 앱으로 가면 풀고 돌아오면 다시 요청합니다. 지원하지 않거나 거절되면(배터리 절약 모드 등) 평소처럼 꺼집니다. 네트워크 요청이 아니라서 CSP와 상관없습니다.
  - 사이트로 돌아가는 `carpenta.github.io` 링크는 모든 화면에 보이지만, 실수로 누르지 않게 머리말 오른쪽 아래에 작게 둡니다.
  - 빠르게 연속으로 눌러도 화면이 확대되거나 글자가 선택되지 않습니다. 가로 화면에서는 위쪽 합계를 고정하지 않습니다.
  - "홈 화면에 추가"하면 앱처럼 전체 화면으로 열립니다(manifest, 아이콘). 아이콘 PNG는 `node scripts/make-icons.mjs`로 만든 것을 커밋해 둡니다.
- 접근성: 탭할 때마다 하나의 알림 영역이 "3번 홀 퍼터 2, 5타"처럼 읽어 주고, Par 선택은 화살표 키로 움직입니다.
- 제한
  - 들어 있는 골프장은 공식 홈페이지에서 홀별 Par를 확인한 곳뿐입니다([코스 데이터](#코스-데이터)). 경상권은 아직 없습니다. Par 3·4·5만 다루므로 Par 6 홀이 있는 코스는 뺐습니다. 티별 거리와 핸디캡(S.I.)은 아직 없습니다.
  - 한 번에 한 라운드를 기록합니다. 동반자 스코어, 거리 측정은 없습니다.
  - 지난 라운드는 이 브라우저에만 있습니다. 기기 사이에 자동으로 옮겨지지 않으니 백업 파일을 씁니다.
  - 화면 문구는 한국어만 있습니다.
- 최신 Chrome에서 검증했습니다.

- 출처: 각 골프장(또는 운영사)의 공식 홈페이지에 공개된 코스 안내·스코어카드의 홀별 Par. 골프장마다 출처 페이지 주소와 확인일을 함께 둡니다. 공공데이터포털(data.go.kr)의 골프장 현황은 목록·홀 수 확인에만 썼고 홀별 Par는 없습니다.

## 오프라인

골프장처럼 신호가 약한 곳에서도 쓸 수 있게, 한 번 열고 나면 인터넷 없이 다시 열고 기록할 수 있습니다.

- 빌드할 때 `vite.config.ts`의 작은 플러그인이 `dist/sw.js`(서비스 워커)를 만듭니다. 빌드된 파일 전체(`index.html`, `assets/*`, 아이콘, manifest) 목록과 파일 내용 해시로 만든 빌드 ID가 들어갑니다.
- 처음 열 때 이 파일들을 브라우저의 Cache Storage(`fairway-note-<빌드 ID>`)에 받아 두고, 그다음부터는 캐시에서 먼저 엽니다. 받을 때 HTTP 캐시를 건너뛰어 배포가 섞이지 않게 합니다.
- 새 버전이 배포되면 바로 바꾸지 않고, 화면 아래에 "새 버전이 있습니다 · 다시 열기" 버튼을 띄웁니다. 기록을 방해하지 않으며, 누르면 새 버전으로 다시 엽니다. 라운드와 지난 라운드는 localStorage에 있으므로 그대로 남습니다.
- 새 버전이 자리를 잡으면 이 도구의 예전 캐시만 지웁니다.
- `npm run dev`에서는 서비스 워커를 등록하지 않습니다. 확인은 `npm run build && npm run preview`로 합니다. 서비스 워커는 `localhost`·`127.0.0.1`이나 HTTPS에서만 동작합니다.

## 개인정보 경계

결과 보내기를 누를 때만, 사용자가 고른 메일 앱이나 공유 대상으로 라운드 내용이 넘어갑니다. 앱이 스스로 보내는 요청은 없습니다.

백업 파일은 사용자가 내려받은 곳(다운로드 폴더, 파일 앱)이나 직접 고른 공유 대상에만 있습니다. 앱은 파일을 어디로도 보내지 않고, 가져오기는 고른 파일을 이 브라우저 안에서만 읽습니다. 파일 형식은 `{ app: "fairway-note", format: 1, exportedAt, current, history }`이고(`current`는 지금 라운드, 입력이 없으면 `null`, `history`는 지난 라운드 배열), 라운드 기록 말고는 기기·계정 정보가 없습니다. 열어 볼 수 있는 JSON이니 다른 사람에게 보내지 않도록 주의하세요.

입력한 라운드는 이 브라우저의 localStorage(`fairway-note:round:v1`) 한 곳에만 저장해 새로고침이나 화면 꺼짐 뒤에도 이어서 기록할 수 있게 합니다. 페이지를 열기만 해서는 저장하지 않고 코스를 고르거나 첫 입력을 할 때 저장합니다. 마지막으로 고른 코스(골프장·9홀 id, 직접 입력한 이름)는 `fairway-note:prefs:v1`에 따로 둡니다. 첫 저장 때 브라우저에 저장소를 지우지 말라고(`navigator.storage.persist()`) 한 번 요청합니다. 샷 세부는 같은 키의 홀마다 선택 항목(`tags`, `obByTag`)으로 저장해 예전 라운드도 그대로 읽습니다(`version: 1` 유지). 세부 일부를 읽을 수 없으면(모르는 칩 값 등) 타수는 그대로 두고 그 세부만 빼고 불러오며, 원래 값은 아래처럼 따로 보관합니다. 저장된 값이 깨졌거나 더 새 버전이 쓴 값이라 읽을 수 없으면 덮어쓰기 전에 `fairway-note:corrupt:<시각>` 키로 따로 보관합니다(최근 3개까지). 보관할 수 없으면 저장하지 않습니다. 새 라운드를 시작하면 바꿉니다(끝낸 홀이 있으면 먼저 지난 라운드에 보관합니다). 지난 라운드는 같은 localStorage의 다른 키 `fairway-note:history:v1`에 `{ id, endedAt, round }` 배열로 저장하고, 라운드마다 지금 라운드와 같은 검사(코스·샷 세부 포함)를 거칩니다. 첫 라운드를 보관할 때 생기고 마지막 라운드를 지우면 없어집니다. 저장된 지난 라운드를 일부라도 읽을 수 없으면(깨진 값, 모르는 필드나 세부) 덮어쓰기 전에 같은 `fairway-note:corrupt:<시각>` 키에 따로 보관하고(지금 라운드의 보관본과 합쳐 최근 3개), 보관할 수 없으면 지난 라운드를 바꾸지 않습니다. 서버로 보내지 않고, sessionStorage·IndexedDB·쿠키는 쓰지 않습니다. Cache Storage에는 앱 파일만 두고 라운드 내용은 넣지 않습니다. 저장할 수 없는 환경(일부 개인정보 보호 모드)에서는 화면 아래에 그렇게 알리고 메모리에서만 동작합니다.

CSP 메타 태그가 네트워크 연결(`connect-src 'none'`)과 다른 출처의 스크립트·스타일·이미지, 인라인 스타일 태그를 막습니다. 그래서 `npm run dev`에서는 Vite가 넣는 스타일도 막히니 화면 확인은 `npm run build && npm run preview`로 합니다.
