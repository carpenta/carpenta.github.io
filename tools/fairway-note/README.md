# Fairway Note — 에버리스 새별·레이크 스코어 노트

라운드 중 휴대폰으로 홀마다 드라이버·어프로치·퍼트 타수를 버튼으로 세고, OB와 멀리건을 함께 표시하는 정적 웹 앱입니다. 합계와 라운드 분석을 입력하는 즉시 보여 줍니다. TypeScript + Vite로 만들었고 런타임 의존성, 백엔드, 계정, 분석 도구가 없습니다.

## 실행

Node.js 22.12 이상이 필요합니다.

```sh
npm ci
npm run dev
```

배포 빌드 확인:

```sh
npm run build
npm run preview -- --port 4175 --strictPort
```

주소: http://127.0.0.1:4175

CSP 때문에 `npm run dev`에서는 자동 새로고침(HMR)과 Vite가 넣는 스타일이 막힙니다. 화면은 빌드 후 미리보기로 확인합니다.

## 기능과 제한

- 18홀: 전반 1–9는 에버리스 새별, 후반 10–18은 레이크 코스입니다. 각 홀의 Par는 골프장 운영사 공식 스코어카드(shinangolf.com, 2026-11-19 확인) 값으로 시작하고(파 72), 홀마다 Par 3·4·5로 고칠 수 있습니다.
- 홀마다 세는 항목
  - 드라이버: 티샷. OB 뒤 다시 친 티샷도 여기에 셉니다.
  - 어프로치: 두 번째 샷부터 그린에 올리기 전까지의 샷
  - 퍼터: 그린 위 퍼트
  - OB: 한 번에 1벌타가 타수에 더해집니다. 다시 친 샷은 드라이버나 어프로치로 따로 셉니다.
  - 멀리건: 표시만 하고 타수에 넣지 않습니다.
- 홀 타수 = 드라이버 + 어프로치 + 퍼터 + OB. 한 항목은 0–15까지 셀 수 있습니다.
- 지금 치고 있는 홀은 퍼트를 넣기 전까지 "진행 중"으로 보이고 합계·스코어카드·분석에 넣지 않습니다(티샷만 친 홀이 이글로 잡히지 않게). 퍼트 없이 끝난 홀(칩인)은 다음 홀로 넘어가면 들어갑니다.
- 위쪽 합계(총타·Par 대비·기록한 홀·퍼트·OB·멀리건)는 화면을 내려도 따라옵니다.
- 스코어카드: 전반·후반 표와 OUT·IN·합계. 홀 번호를 누르면 그 홀로 갑니다.
- 라운드 분석(기록한 홀만 대상)
  - 평균 퍼트, 1퍼트·3퍼트 이상 홀 수
  - 그린 적중(GIR): 퍼트가 있고 드라이버 + 어프로치 + OB ≤ Par − 2인 홀
  - 스코어 분포(이글 이하 ~ 트리플 이상), Par별 평균, 가장 잘한·아쉬운 홀
  - 영역별 잃은 타수: 홀마다 티샷 1, 어프로치 Par − 3, 퍼트 2를 기준으로 더 친 타수와 OB 벌타. 기준보다 적게 친 홀이 다른 홀의 손실을 지우지 않습니다. 가장 많이 잃은 영역(같으면 모두)을 알려 줍니다.
- 결과 보내기
  - 이메일로 보내기: 휴대폰 메일 앱이 열리고 제목(코스·날짜·타수)과 본문(합계, 끝낸 홀별 타수, 분석)이 채워집니다. 받는 사람은 메일 앱에서 넣습니다. 이 앱이 메일을 직접 보내지는 않습니다(`mailto:` 링크).
  - 공유하기: 휴대폰 공유 시트(카카오톡·문자 등)로 같은 내용을 보냅니다. 공유 시트가 없는 브라우저에서는 "결과 복사"로 클립보드에 복사합니다.
- + 버튼에는 항목별 아이콘(드라이버 헤드, 아이언, 퍼터, OB 말뚝, 다시 치기)이 있습니다.
- 다른 날 기록하던 라운드가 남아 있으면 열 때 "이어서 기록 / 새 라운드 시작"을 묻습니다.
- 같은 브라우저의 다른 탭에서 기록하면 열려 있는 탭도 그 기록으로 바뀝니다.
- 휴대폰 화면
  - 이전·다음 홀 버튼은 화면 아래에 고정되어 엄지로 바로 누릅니다(홈 인디케이터 여백 포함).
  - 홀을 옮기면 홀 카드가 위쪽 합계 바로 아래로 와서, 375×553(Safari 막대를 뺀 iPhone SE 크기)에서도 Par 선택, 다섯 항목과 아래 버튼이 한 화면에 들어옵니다. 높이가 700px 이하인 화면에서는 위쪽 합계를 한 줄로 줄이고 항목 설명을 숨깁니다.
  - 햇빛 아래에서도 읽히도록 작은 글자(합계 이름, 홀 번호, 항목 설명, 스코어카드 행 이름)는 13px 이상, 흰 바탕 대비 4.5:1 이상입니다. 누를 수 있는 − 버튼은 초록 테두리로, 누를 수 없는 것은 흐리게 보입니다.
  - 라운드를 여는 동안 화면이 꺼지지 않게 Screen Wake Lock을 요청합니다. 다른 앱으로 가면 풀고 돌아오면 다시 요청합니다. 지원하지 않거나 거절되면(배터리 절약 모드 등) 평소처럼 꺼집니다. 네트워크 요청이 아니라서 CSP와 상관없습니다.
  - 사이트로 돌아가는 `carpenta.github.io` 링크는 모든 화면에 보이지만, 실수로 누르지 않게 머리말 오른쪽 아래에 작게 둡니다.
  - 빠르게 연속으로 눌러도 화면이 확대되거나 글자가 선택되지 않습니다. 가로 화면에서는 위쪽 합계를 고정하지 않습니다.
  - "홈 화면에 추가"하면 앱처럼 전체 화면으로 열립니다(manifest, 아이콘). 아이콘 PNG는 `node scripts/make-icons.mjs`로 만든 것을 커밋해 둡니다.
- 접근성: 탭할 때마다 하나의 알림 영역이 "3번 홀 퍼터 2, 5타"처럼 읽어 주고, Par 선택은 화살표 키로 움직입니다.
- 제한
  - 코스는 새별(전반)·레이크(후반) 조합으로 고정입니다. 파인 코스나 다른 조합, 다른 골프장은 아직 고를 수 없어 Par를 직접 고쳐야 합니다. 이미 저장된 라운드의 Par는 바꾸지 않습니다.
  - 라운드 하나만 기록합니다. 지난 라운드 보관, 동반자 스코어, 거리 측정은 없습니다.
  - 화면 문구는 한국어만 있습니다.
- 최신 Chrome에서 검증했습니다.

## 오프라인

골프장처럼 신호가 약한 곳에서도 쓸 수 있게, 한 번 열고 나면 인터넷 없이 다시 열고 기록할 수 있습니다.

- 빌드할 때 `vite.config.ts`의 작은 플러그인이 `dist/sw.js`(서비스 워커)를 만듭니다. 빌드된 파일 전체(`index.html`, `assets/*`, 아이콘, manifest) 목록과 파일 내용 해시로 만든 빌드 ID가 들어갑니다.
- 처음 열 때 이 파일들을 브라우저의 Cache Storage(`fairway-note-<빌드 ID>`)에 받아 두고, 그다음부터는 캐시에서 먼저 엽니다. 받을 때 HTTP 캐시를 건너뛰어 배포가 섞이지 않게 합니다.
- 새 버전이 배포되면 바로 바꾸지 않고, 화면 아래에 "새 버전이 있습니다 · 다시 열기" 버튼을 띄웁니다. 기록을 방해하지 않으며, 누르면 새 버전으로 다시 엽니다. 라운드는 localStorage에 있으므로 그대로 남습니다.
- 새 버전이 자리를 잡으면 이 도구의 예전 캐시만 지웁니다.
- `npm run dev`에서는 서비스 워커를 등록하지 않습니다. 확인은 `npm run build && npm run preview`로 합니다. 서비스 워커는 `localhost`·`127.0.0.1`이나 HTTPS에서만 동작합니다.

## 개인정보 경계

결과 보내기를 누를 때만, 사용자가 고른 메일 앱이나 공유 대상으로 라운드 내용이 넘어갑니다. 앱이 스스로 보내는 요청은 없습니다.

입력한 라운드는 이 브라우저의 localStorage(`fairway-note:round:v1`) 한 곳에만 저장해 새로고침이나 화면 꺼짐 뒤에도 이어서 기록할 수 있게 합니다. 페이지를 열기만 해서는 저장하지 않고 첫 입력부터 저장합니다. 첫 저장 때 브라우저에 저장소를 지우지 말라고(`navigator.storage.persist()`) 한 번 요청합니다. 저장된 값이 깨졌거나 더 새 버전이 쓴 값이라 읽을 수 없으면 덮어쓰기 전에 `fairway-note:corrupt:<시각>` 키로 따로 보관합니다(최근 3개까지). 보관할 수 없으면 저장하지 않습니다. "새 라운드 시작"을 누르면 지웁니다. 서버로 보내지 않고, sessionStorage·IndexedDB·쿠키는 쓰지 않습니다. Cache Storage에는 앱 파일만 두고 라운드 내용은 넣지 않습니다. 저장할 수 없는 환경(일부 개인정보 보호 모드)에서는 화면 아래에 그렇게 알리고 메모리에서만 동작합니다.

CSP 메타 태그가 네트워크 연결(`connect-src 'none'`)과 다른 출처의 스크립트·스타일·이미지, 인라인 스타일 태그를 막습니다. 그래서 `npm run dev`에서는 Vite가 넣는 스타일도 막히니 화면 확인은 `npm run build && npm run preview`로 합니다.

## 검증

```sh
npm test
npx playwright install chromium
npm run test:e2e -- --workers=1
```

- 단위 테스트(Vitest)
  - 홀 타수, OB 벌타, 멀리건 제외, 0–15 범위
  - 진행 중인 홀과 칩인 처리
  - GIR, 스코어 이름, 합계, 분석(분포·Par별 평균·영역별 손실·동률·가장 잘한/아쉬운 홀)
  - 보고서 문장, 메일 제목·본문, `mailto:` 인코딩
  - 저장·복원, 깨진 값(없는 날짜 포함) 무시, 저장소 예외, 읽을 수 없는 값 따로 보관(중복·개수 제한·보관 실패 시 저장 거부), `lastEdited` 없는 예전 라운드, 12시간 기준 지난 라운드 판단
  - 화면 켜짐: 보일 때 요청, 숨기면 해제, 돌아오면 다시 요청, 미지원·거절 무시
  - 서비스 워커: 캐시 목록과 빌드 ID, 설치·스스로 활성화하지 않음·`SKIP_WAITING`·예전 캐시 정리, 캐시 우선 응답과 그 밖의 요청 통과
- e2e(Playwright Chromium)
  - 탭으로 기록, 빼기, Par 변경, 합계와 스코어카드
  - 분석 문구
  - 새로고침 뒤 복원, 새 라운드 확인·취소, 깨진 저장 값, 읽을 수 없는 값을 덮어쓰지 않고 보관, 열기만 해서는 저장하지 않음
  - 스코어카드에서 홀 이동, 처음·끝 홀
  - 휴대폰(375×600 터치): 한 화면에 모든 항목과 홀 버튼, 375×553·390×664에서 다음 홀로 가면 홀 카드 전체(− / + 버튼, Par 선택)가 합계와 아래 버튼 사이에 보임, 합계 높이에 맞춘 스크롤 여백, 글자 크기·대비, − 버튼 상태, 화면 켜짐 요청과 미지원·거절 시 오류 없음, 페이지 끝이 아래 버튼에 가리지 않음, 320px 폭, 홈 화면 추가용 manifest·아이콘
  - 진행 중인 홀, 칩인, 멀리건만 있는 홀, 15에서 멈춤
  - 스코어카드에서 이동한 뒤 홀 제목이 위쪽 합계에 가리지 않음, Par 화살표 키, 알림 영역
  - + 버튼 아이콘, 이메일 링크 내용, 공유 시트 호출, 공유가 없을 때 복사
  - 저장할 수 없는 환경, 지난 라운드 안내(이어서 기록 뒤 다시 묻지 않음, 새 라운드 확인), 자정을 넘긴 라운드, 다른 탭과 동기화, 다른 탭에서 지운 경우
  - 오프라인: 한 번 연 뒤 인터넷 없이 새로고침해도 화면과 탭 기록이 동작, 빌드된 `sw.js`의 캐시 목록, 새 버전 안내 버튼과 다시 열기
  - 콘솔 오류·CSP 위반 없음, 외부 요청 없음, 라운드 키(와 읽을 수 없는 값의 보관 키) 외에 저장소 사용 없음, `../../` 링크, 360px 폭에서 가로 스크롤 없음

## 배포

이 도구는 `carpenta.github.io` 저장소의 `tools/fairway-note/`에 있고, `https://carpenta.github.io/tools/fairway-note/`로 서비스됩니다. 저장소 루트의 `.github/workflows/pages.yml`이 테스트와 빌드를 실행한 뒤 사이트와 함께 배포합니다. `base: './'`이므로 하위 경로에서 그대로 동작합니다.
